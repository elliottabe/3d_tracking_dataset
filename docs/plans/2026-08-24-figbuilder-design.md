# figbuilder — interactive paper-figure composer

**Date:** 2026-08-24
**Status:** design approved, not implemented
**Motivating artifact:** `notebooks/Courtship_Song_Figures2.ipynb` cell 8 →
`figures/paper_figures/fig4_050426_ETTA.svg`

## Problem

Figure 4 of the courtship-song paper is produced by a single 29 KB notebook
cell that hard-codes a dozen absolute paths, runs the full song-analysis
pipeline, and calls `utils.courtship_figure_panels.assemble_figure` — a
four-level nest of matplotlib subfigures whose whitespace is tuned by
fifteen scattered `subplots_adjust` calls. The matplotlib SVG is then
hand-edited in Inkscape: panel letters and captions retyped as Arial
`<text>`, leader lines and brackets added, a highlight rect drawn.

Three things are wrong with this.

1. **It is not regenerable.** Reproducing the figure means re-running a
   notebook against `/data2` paths that exist on exactly one machine, then
   repeating an unrecorded Inkscape session. Inkscape also flattens
   matplotlib's `figure_1`/`axes_N` group structure, so the hand edits
   cannot be replayed onto a fresh export.
2. **Layout iteration is slow and blind.** Changing a gutter means editing a
   number in a Python file, re-running a cell that decodes video and drives
   MuJoCo, and looking at the result.
3. **Nothing is reusable.** The next figure starts from another bespoke
   `assemble_figure`.

## Goals

- Regenerate Figure 4 headlessly from committed inputs with one command.
- Edit layout — subfigure geometry, sizes, whitespace — interactively and
  smoothly, with real alignment tooling.
- Own the annotation layer (letters, captions, arrows, brackets, imported
  graphics) so Inkscape becomes optional rather than required.
- Generalise: a reusable panel registry, so the next figure is configuration
  rather than a new bespoke assembler.

## Non-goals

- Replacing the analysis pipeline. `utils/courtship_figure_panels.py`,
  `utils/song_analysis.py` and friends are consumed unmodified.
- A general-purpose vector editor. The annotation layer covers what paper
  figures need; Inkscape remains available for anything exotic.
- Publishing or hosting. This is a local tool.

## Architecture

Four components. One strict rule: **matplotlib is the only chart renderer.**
The browser never draws a chart — it positions tiles matplotlib already made.

```
   heavy pipeline (scripts/figures/export_fig4_bundle.py)   ← runs once, on the data machine
              │  export_bundle()
              ▼
   bundle.h5  ─ plot-ready arrays + baked image assets (video frames, MuJoCo renders)
              │
   ┌──────────┴───────────────────────────────┐
   │  figbuilder serve   (FastAPI, repo env)  │
   │   • GET  /api/bundle    panel + dataset inventory
   │   • POST /api/panel     render ONE panel → SVG tile  (disk-cached)
   │   • POST /api/export    figure.json → .svg/.pdf/.png
   │   • GET  /api/dataset   raw array, for pickers/previews
   └──────────┬───────────────────────────────┘
              │  SVG tiles + arrays
              ▼
   browser editor (Vite + React + zustand, SVG canvas)
              │  writes
              ▼
   figure.json  ─ rects, groups, labels, annotations   ← small, git-committed
```

### The two-artifact split

`bundle.h5` is **data**: large, gitignored under `figures/`, regenerated by
the pipeline. `figure.json` is **design**: a few KB, committed, readable and
hand-editable.

This split is what makes the figure regenerable. `python -m figbuilder export
figure.json --bundle bundle.h5 -o fig4.svg` reproduces the paper figure with
no browser and no notebook. The web app is how you *author* `figure.json`; it
is not required to *use* it.

### Bundle contract

```
bundle.h5
  /meta                      attrs: created, source_script, repo_commit,
                                    fig_width_mm, fig_height_mm
  /panels/<panel_id>/
      attrs: type            e.g. "line", "violin", "courtship.wing_z"
      data/<name>            plot-ready arrays (1-D/2-D float, or structured
                             arrays for segment tables)
      assets/<name>          uint8 image arrays (video frames, MuJoCo renders)
                             with attrs: extent, dpi
```

Segment tables (`seg_L`, `seg_R`) are stored as structured arrays with fields
`(start:i8, end:i8, type:S8)`.

Panels whose content is a rendered image — the video strip and the MuJoCo
render strip — bake their frames into `assets/` at export time. They are
therefore **never re-rendered during editing**, which removes MuJoCo and
video decoding from the interactive loop entirely.

### figure.json contract

```jsonc
{
  "version": 1,
  "bundle": "bundle.h5",              // relative to this file
  "figure": {"width_mm": 183.0, "height_mm": 140.0, "dpi": 300,
             "transparent": true},
  "style": {                           // becomes matplotlib rcParams
    "font.family": "sans-serif",
    "font.sans-serif": ["Arial", "Helvetica", "DejaVu Sans"],
    "font.size": 6.0
  },
  "panels": [
    {"id": "wing", "type": "courtship.wing_z",
     "rect": [0.07, 0.62, 0.90, 0.14],           // figure fractions
     "group": "row2", "z": 0,
     "data": {"t_ms": {"dataset": "/panels/wing/data/t_ms"},
              "wingL_z": {"dataset": "/panels/wing/data/wingL_z"}},
     "spec": {"fs": 800.0, "time_unit": "s", "min_segment_ms": 10.0}}
  ],
  "groups": [
    {"id": "row2", "axis": "y", "gutter_mm": 1.2, "equal": false,
     "rect": [0.07, 0.55, 0.90, 0.21]}
  ],
  "annotations": [
    {"id": "letter_wing", "kind": "text", "managed": "panel_letter",
     "parent": "wing", "pos_mm": [-4.0, 2.0],
     "text": "C", "style": {"font_size_pt": 8, "weight": "bold"}}
  ]
}
```

Rects are always root-figure fractions. A panel inside a group keeps its
solved rect written out, so the file is fully renderable without running the
group solver — the group is an editing convenience, not a render dependency.

### HTTP API

| Route | Request | Response |
|---|---|---|
| `GET /api/bundle` | — | `{meta, panels: [{id, type, data: {name: {shape, dtype}}, assets: [...]}]}` |
| `POST /api/panel` | `{panel, style, width_pt, height_pt}` | `{svg, ink_box_pt, cache_hit}` |
| `GET /api/dataset` | `?path=/panels/wing/data/t_ms&max=4000` | decimated JSON array, for pickers and previews |
| `POST /api/export` | `{figure_json, formats: ["svg","pdf"]}` | `{paths, warnings}` |

`ink_box_pt` is returned with every tile because the front-end needs it for
ink-box alignment and cannot compute matplotlib text metrics itself.

### Rendering and caching

A panel tile is an SVG produced by rendering exactly one panel into a
one-axes figure at the requested size. The cache key is
`hash(panel spec + rect size in pt + rcParams)`, stored on disk under
`figures/.figbuilder_cache/`.

Consequences for interactivity:

| Edit | Renders triggered |
|---|---|
| Move a panel, change a gutter, edit an annotation | 0 |
| Resize one panel | 1 |
| Rebind a panel's data or change its spec | 1 |
| Change figure size | all (debounced) |

Resize triggers a render because matplotlib tick and axis-label text does not
scale with the axes box; a stretched tile would misrepresent the output.

### Composition and export

Export composes a single SVG document:

1. Each panel tile is inserted as `<g transform="translate(x,y) scale(s)">`.
2. The annotation layer is appended.
3. The result is written as `.svg`; `.png` and `.pdf` are derived from it.

Because the annotation layer in the editor and in the export is the same SVG,
and the panels in the editor are literally matplotlib's output, WYSIWYG is
exact — nothing is drawn twice by two engines.

Two implementation notes:

- **Id namespacing.** matplotlib emits SVG `clipPath` and glyph ids
  (`C3_0_ad4e761f83`) that collide across tiles. Every tile's ids are
  rewritten with a per-panel prefix during composition.
- **Text.** `svg.fonttype: "none"` and `pdf.fonttype: 42` so all text exports
  as real, editable `<text>` in the configured font — the thing the Inkscape
  pass was recreating by hand. Each axes carries a `gid`, so the output has
  named nested groups rather than a flat element soup.

**PDF is a derived format, not a native one.** matplotlib's PDF backend
cannot place an imported SVG asset. PDF is produced from the composed SVG via
`inkscape --export-type=pdf` when available, with `cairosvg` as fallback.
SVG is the primary deliverable.

## Layout model

**Source of truth is an absolute rect per panel** — `[x, y, w, h]` in figure
fractions, matching `fig.add_axes` semantics. Stored as fractions; edited and
displayed in millimetres, with points available. Figure size is specified in
mm, so 183 mm double-column stays a first-class number.

### Two boxes, always

A panel has an **axes box** (the rect) and an **ink box** (tight bbox
including tick labels and axis labels). They are never the same. Aligning by
axes box makes data comparable across panels; aligning by ink box makes
margins tidy. Every align, distribute and snap operation therefore takes an
explicit `align-by: axes | ink` mode, defaulting to `axes`.

### Manipulation

- **Snapping** to figure margins, neighbour edges and centres (in both box
  modes), a 1 mm grid, and draggable ruler guides. Magenta smart-guide lines
  appear live during a drag. Tolerance is in screen pixels, so it is
  zoom-independent.
- **Align / distribute**: left, h-centre, right, top, v-centre, bottom;
  distribute by equal gaps or equal centres; match-width, match-height.
  Relative to selection bbox, first-selected, or the figure.
- **Numeric entry** of x/y/w/h in mm, with aspect lock.
- **Arrow-key nudge**: 0.25 mm, 1 mm with Shift.
- **Undo/redo** over a full command stack.

### Groups

Panels may be tagged into a row or column group carrying a single gutter
value and an optional equal-size flag; the group solves its children's rects.
This gives declarative whitespace where it is wanted — the six-frame video
strip becomes one gutter instead of six rects — while everything outside a
group stays freely placed. Ungrouping leaves children at their current
absolute rects.

## Annotation layer

Objects: text, arrow (with head styles), line, leader, rect, ellipse,
curly/square bracket, scale bar, imported SVG, imported PNG.

Each object is either figure-anchored or parented to a panel, in which case
it travels with that panel. All objects are z-ordered and are snappable and
alignable by the same tools as panels.

**Panel letters and captions are managed annotations**: auto-created per
panel, auto-lettered in reading order, with manual override and a "relabel in
current order" action. Each is independently draggable and restylable. This
is the step that consumed most of the Inkscape session, and it becomes
automatic-with-override.

### Deliberate duplication

The annotation SVG emitter exists twice — TypeScript for 60 fps live editing,
Python for headless export, roughly 150 lines each. A conformance test
renders a fixture containing every annotation type through both emitters and
asserts equivalent normalised SVG.

The alternative — making headless export depend on a browser — is worse. The
duplication is bounded, mechanical, and test-guarded.

Layout *geometry* math is **not** duplicated: it lives in TypeScript only,
because it only ever runs in the browser. Python's export consumes finished
rects.

## Panel registry

A panel type is a Python class carrying a JSON schema:

```python
@register("courtship.wing_z")
class WingZPanel(PanelType):
    label  = "Wing V13 z + song segments"
    schema = {...}                      # drives the properties form
    needs  = ["t_ms", "wingL_z", "wingR_z", "seg_L", "seg_R"]

    def draw(self, ax, data, spec):
        cfp.panel_wing_z_traces(ax, data["t_ms"], data["wingL_z"],
                                data["wingR_z"], data["seg_L"],
                                data["seg_R"], **spec)
```

The schema auto-generates the front-end properties UI, so **adding a panel
type is Python-only** — no per-panel JavaScript.

**Generic types**: `line`, `scatter`, `image`, `hist_kde`, `violin`, `box`,
`strip`, `polar`, `bar`, `heatmap`, `blank`.

**Courtship adapters**: one ~15-line adapter per existing `panel_*` function
in `utils/courtship_figure_panels.py`, which is not modified.

Data is referenced as `{"dataset": "/panels/wing/data/t_ms", "slice":
"0:800"}`, pointing into the bundle. Rebinding a panel to different data is a
dropdown populated from `/api/bundle`.

One improvement falls out of the model: `video` and `render` are currently
*lists* of axes. Each frame becomes its own panel inside a group, so a single
frame can be nudged and the frame count changed without touching
`assemble_figure`.

## Layout of the code

```
figbuilder/
  bundle.py           read/write bundle.h5
  panels/
    base.py           PanelType, register, schema plumbing
    generic.py        line, scatter, image, violin, density, polar, bar, heatmap
    courtship.py      adapters over utils.courtship_figure_panels
  render.py           panel -> SVG tile, disk cache
  compose.py          tiles + annotation SVG -> final document
  annot.py            Python annotation SVG emitter
  export.py           figure.json -> svg/pdf/png
  server.py           FastAPI
  cli.py              serve / export / bundle-info
web/
  src/layout/         snap, align, distribute, group solve (pure TS, unit-tested)
  src/annot/          TS annotation SVG emitter
  src/canvas/         SVG canvas, selection, guides, rulers
  src/props/          schema-driven properties forms
scripts/figures/
  export_fig4_bundle.py
figures/paper_figures/
  fig4.json           committed design artifact
```

`bundle.h5` and `.figbuilder_cache/` live under `figures/`, already
gitignored.

## Milestones

**M0 — bundle contract + export CLI, no UI.**
Extract cell 8's pipeline into `scripts/figures/export_fig4_bundle.py`. Seed
`fig4.json` by rendering the current figure once and dumping each axes'
rect. Note that `ax.get_position()` returns coordinates relative to the
axes' parent *SubFigure*, not the root figure, and `assemble_figure` nests
subfigures three deep — so each rect must be transformed to root-figure
fractions via `ax.get_window_extent()` and the root figure's
`transFigure.inverted()`. `figbuilder export` then reproduces the figure
headlessly.

*Acceptance gate is visual.* Stated expectation: the exported SVG places
every panel at the same rect as `fig4_050426_ETTA.svg`, with identical
traces; panel letters and captions will differ, because those were hand-placed
in Inkscape and M0 does not yet own them. Both are rendered to PNG, compared
side by side, and the comparison is read back and reported — including
disagreement. A figure generated but not viewed is not evidence.

**M1 — server + read-only canvas.** Tiles render, panels display at correct
rects, zoom and pan work. Proves tile composition and id namespacing.

**M2 — layout editing.** Drag, resize, snap, guides, align/distribute,
numeric entry, groups, undo. The largest milestone.

**M3 — annotation layer.** Text, managed letters and captions, arrows,
brackets, shapes, SVG/PNG import.

**M4 — data rebinding and generic panels.** Dataset dropdowns, panel-type
switching, add and delete panels.

**M5 — live server mode (optional).** The same API backed by the live
analysis pipeline rather than a frozen bundle, so new bouts and thresholds
can be explored without re-bundling.

## Testing

- **Layout math** (snap, align, distribute, group solve): pure TypeScript
  functions, unit-tested in the front-end.
- **Bundle**: write/read round-trip preserves arrays, dtypes, and attrs.
- **Panel adapters**: one smoke test per registered type, asserting it draws
  without error given its declared `needs`.
- **Annotation emitters**: conformance test across a fixture of every
  annotation type, TS output vs Python output, normalised.
- **Export determinism**: the same `figure.json` + bundle yields byte-identical
  SVG, modulo the embedded timestamp.
- **Golden structure**: `fig4.json` against a small committed fixture bundle
  produces an SVG with the expected panel count, `gid`s, and text content.
- **Visual regression**: the M0 acceptance render is repeated at each
  milestone and read back.

## Risks

| Risk | Mitigation |
|---|---|
| matplotlib SVG id collisions across tiles | Per-panel id prefixing in `compose.py`; covered by the golden structure test |
| PDF fidelity through the SVG conversion | SVG is the primary output; Inkscape CLI preferred over cairosvg; PDF checked at M0 |
| Font metrics differ between browser preview and export | Panels are matplotlib output in both; annotations use the same SVG in both. Only the *canvas* font must match, which it does because it renders the same `<text>` |
| Bundle export drifts from the notebook | `export_fig4_bundle.py` becomes the single source; the notebook imports it rather than duplicating cell 8 |
| Scope creep toward a general vector editor | The annotation object list in this spec is closed; additions need a new design pass |
